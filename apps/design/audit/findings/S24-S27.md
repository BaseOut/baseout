## 1 Job

**Source:** *hand Baseout an Airtable account it may read, and give it a name I will recognise later.*
**Destination:** *tell Baseout where backups are written, and give that a name too.*

**STATED, partially.** `specs/07-integrations.md` and the product model cover the account-level
registry (`decision-account-destinations`: a reusable account object, later linked to Spaces), and
both files restate the job in their own header comments (`SourceAddView.astro:2-17`,
`DestinationAddView.astro:2-15`). What no spec states is **what a create is supposed to leave behind**
— whether submitting a PAT produces a *connected* source or one still needing connection. The
harness answers `needs_connection` (`apps/design/src/fixtures/sources.ts:76-89`, `account: 'token ••••'`)
while the button says `Create source`. Recorded as F18, a question for the client's engineer, not a
defect.

  **"Add source · Core CRM"** and the h1 underneath paints **"Add an Airtable source"**
  (Destinations: "Add destination" vs "Add a destination"). See F1.
- *What do I do next* — answered on Destinations step 1 (nine cards, two labelled groups) and on

  reader has not chosen yet, and still fully expanded after they choose PAT

## 3 Navigation and orientation

- **Arrival** — from the registry's `Add source` / `Add destination` CTA; both pages open with a
  `← Sources` / `← Destinations` back-link as the first element. Consistent across the family. ✓
- **The URL carries the state, on both surfaces and correctly.** `?method=pat` deep-links the PAT
  branch (measured: `patChecked: true`, token field visible on load) and `?type=postgres` deep-links
  destination step 2. Both survive a refresh and are shareable. This is the contract
  `pattern-settings-drill` asks for, achieved with no client state at all. ✓
- **`?type=<unknown>` is swallowed silently** — `/destinations/new?type=bogus` renders step 1 with no
  message and the bad parameter still in the address bar (measured). F14.
- **Departure** — Source: `Cancel` → `/sources`. Destination: `Back` → `/destinations/new`,
  `Cancel` → `/destinations`. Three exits in one slot, two of them the same `btn-sm btn-ghost`
  (measured classes), and all three discard typed input with no prompt (F11).
- Sidebar marks **Sources** / **Destinations** active on the create route (`/sources/new` under the
  Account cluster). ✓ No breadcrumb claims a false parent — the harness passes
  `getBreadcrumbs('/settings')` for both, which is a harness detail, not a rendered lie.

## 4 Primary action

Exactly one primary on every state, right-aligned, solid `btn-primary`, verb-first:
`Authorize and create` (OAuth) / `Create source` (PAT) / `Create destination`. The label branching
on the method is done in pure CSS (`:has()`, `SourceAddView.astro:147-148`) — no JS, no flash. This
is right and is in "do not touch".

Two faults on it: it is **raw markup rather than the catalog `Button`**, and it has **no in-flight
state at all** (F10); its glyph disagrees with its twin (`lucide--plug` vs `lucide--check`, F15).

## 7 Cross-surface consistency

Against the reference surfaces (Schema · Data · Reports) and against each other:

- **Save contract.** Neither form is an editable-object surface, so D30's Read → Edit →
  Save+Cancel-in-one-slot does not apply; both are create forms whose `Cancel` leaves, which S20
  established as correct. **The two forms agree with each other on the submit half** — one real
  `<form>`, one real `<button type=submit>`, the same validator, the same
  `/registry?status=added&name=…` landing (verified identical code, diff = one comment). Where they
  do **not** agree with anything is the **exit** half: D30's "a dirty state gates every exit" is
  unimplemented app-wide (`grep -rn beforeunload apps/web/src` → **0**, including in the file D30
  says it shipped in), and Destinations puts a third exit (`Back`) in the slot wearing Cancel's
  exact classes. F11.
- **Segmented control.** The app has one canonical implementation with four named legacy aliases and
  a comment saying *"there is still exactly ONE rule to change, never a local copy"*
  (`global.css:2470-2520`). This form has the local copy. F5.
- **Errors.** Every other surface that shows a field error uses `TextInput`'s `error` prop. These two
  render a sibling paragraph instead. F3/F4.
- **Page title.** 23 of 29 `<h1>`s use `.text-title`; the six that do not include these three lines
  (`specs/16-responsive.md` §7 names them). F1.
- **Icons.** `lucide--plug` (source primary) vs `lucide--check` (destination primary) for the same
  act; and inside the destination picker, three of nine rows carry full-colour brand marks while six
  carry monochrome Lucide glyphs. F15 / F16.

Direct, second person, no exclamations, verbs on every button. Good lines:
*"Connect once, reuse across Spaces."*, *"Optional — your file backup runs without it."*,
*"Each Space writes to its own subfolder."*

- **Two names for one page** (bar vs h1), on both surfaces — F1.
- **One family, two promises about a secret.** The connection string says *"Stored encrypted."*

  an Airtable credential, says only where to make the token (`SourceAddView.astro:90`). F7.

  you typed.
- `Create the token in Airtable's builder hub with exactly the scopes above` — "the scopes above"
  is correct only while `AccessScopeNote` stays above the field; it is a positional reference in
  body copy (noted with F19).

## 10 Density and rhythm

Measured at 390 and 1440, both surfaces:

- **Horizontal overflow: zero.** `documentElement.scrollWidth === clientWidth` at 390 and 1440 on all
  seven URLs; no element's right edge exceeds the client width. §9's "0 routes overflow" holds. ✓
- **One left edge** at 390: back-link, form, note, every field and the section titles all at **x=12**
  (`#layout-content`'s 12px frame). ✓
- **Type ladder.** Everything painted is on a rung and nothing is below the 11px floor: `.asn code`
  11 (annotated), badges 12→**11**, `.reg-section-title` 16→**14**, `.reg-hint`/`.reg-note` 12→11,
  segment labels 13→**12**, inputs 14→**12**. The three exceptions are the two `<h1>`s (20 and 24 at
  **both** widths — Tailwind literals the compact remap cannot reach, F2) and the error `<p>` at
  **16 at both widths** (F3). So on this surface the tokenised rules step correctly and only the
  literals are frozen — a clean demonstration of §2's [MINE] rule.
- **Control floor.** At 390 inputs and buttons compute **28px** = `--control-min` exactly ✓. Two
  controls are outside the rule that grants it: the segment option (`<span>`, 34px) and the
  back-link (`<a>`, 18px). On a coarse pointer the buttons go to 44 and those two do not (F6).
- **Spacing** is on the 4px grid in both `<style>` blocks (4 · 8 · 12 · 16 · 20); the only off-grid
  values are radii (9.6 / 7.2 / 8.8 / 9px) — instances of **X-A**, not new rows.
- Destination picker reflows 3-up (1440) → 2-up (500) → 1-up (390) from `auto-fill minmax(13rem)`,
  with no media query and no overflow. ✓

## What is good here — do not touch

- **The form is a real form.** `<form method="POST" action="…">` with a real `<button type="submit">`
  inside it, `novalidate` so the app words its own errors, `Enter` submits, and validation runs
  before navigation. Both of these pages previously threw away everything the user typed
  (`J08-F5`, `J08-F13` in the register); that is fixed and the fix is load-bearing.
- **The method choice is a radio group, not a tablist.** `role="radiogroup"`, real radios sharing a
  name, arrow keys work natively, and `:has(input:focus-visible)` paints a real focus ring. The
  catalog says in as many words that *"a choice that gets submitted is a radio"* — this is the
  surface that got it right.
- **No JavaScript decides what the form looks like.** The branch panels and the branching submit
  label are `:has()` selectors (`SourceAddView.astro:145-148`); there is no flash, and the PAT branch
  is correct in the HTML the server sent.
- **The URL is the state.** `?method=pat` and `?type=postgres` deep-link, refresh and share correctly,
  with no store and no history shim.
- **The validator's "visible required only" rule** (`:188-192`) is the right instinct — a hidden
  branch must not block a submit. (F8 asks for the same instinct applied to what gets *sent*.)
- **The shared `.reg-*` style block is byte-identical across the two files** — verified by diff. That
  is what will make the next divergence show up in a review instead of on a screen.
- **The token never reaches the URL, and the browser does not restore it on Back** — measured, and it
  is the correct behaviour for a credential.
- **Zero horizontal overflow, one left edge at x=12, and every tokenised rule steps correctly at 390.**
  The picker grid reflows 3 → 2 → 1 with no media query at all. On a surface that has never had a
  responsive pass, that is a good result and the fixes above are all type and target-size, not layout.
- **`AccessScopeNote` itself** — the content, the Airtable-scope naming and the grouping that mirrors
  Airtable's own consent screen. F19 is about where it sits, never about whether it should exist.
