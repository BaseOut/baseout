## 1 Job

**Set up a place to back up to once, on the account, and reuse it across every Space — and see, and
safely act on, which Spaces depend on it before you touch it.**

**UNSTATED in `specs/`, and that is a finding.** There is no `specs/` page for Destinations. The
word appears only as a bullet — *"Currently-connected storage destinations"* under Settings ▸
Integrations (`specs/12-settings.md:101`) and *"Pick a storage destination"* as step 4 of the
integrations wizard (`specs/07-integrations.md:28`). The account-level *registry* model — created
once, reused, with an "in use by" indicator — exists only in the memory decision
`decision-account-destinations` and in the views' own header comments
(`DestinationsView.astro:3-9`). The register already knows this: **J08-F24 is `DEFER`, trigger
"client confirms `decision-account-destinations`"**. Recorded here as the reason lens 1 cannot be
answered from `specs/`, not as a new row.

The views answer the job as written. Where they fail is the second half of it — *safely act on* —
see F4.

## 3 Navigation and orientation

- **Arrive:** sidebar ▸ Account ▸ Destinations (marked active, verified in the shot). **Leave:**
  a row click, or the `.back-link` on the detail. Both correct.
- **Breadcrumb truth:** the harness passes `getBreadcrumbs('/settings')` for a route that is
  `/destinations` (`pages/destinations.astro:8`, `destinations/detail.astro:9`) — harness-side, and
  the same on Sources. Not filed.
- **URL carries the state:** the object id does (`?id=`), and the not-found path is now scoped and
  correct. The **list's** state does not — sort column and direction live only in
  `wireTableSort`, so a triaged view cannot be linked. That is **D07 (addressable state)**, an
  already-bound class; recorded as an instance, not re-filed.
- **The URL also carries a lie on one path** — see **F2**. `?new=1&type=` reconstructs the object
  from its provider, and the typed name is not in the URL, so the same object has two names one
  click apart.

## 4 Primary action

**List:** exactly one, `Add destination`, `btn btn-primary` (measured 40px, solid `rgb(92,206,255)`),
top-right in `.page-head`, and it disappears in the empty state so the empty card's `btn-sm` primary

**Detail:** one, and it is state-dependent — `Reconnect` (`reconnect`) / `Connect`

Verbs are the user's words throughout: Add · Reconnect · Connect · Remove · Test connection. No
"Configure", no "Manage".

## What is good here — do not touch

- **The list table is the app's best listing frame, and the reason is written down.** Frame outside,
  scroller inside, `data-narrow-pan` on the scroller (`DestinationsView.astro:109-119`) — because
  `panRail` inserts its bar as a **sibling** before the scroller, so with one element the rail
  painted across the card's top border. Verified at 390: the rail is a child of the frame
  (`.reg-tableframe > .pan-rail, .reg-tablewrap`). The comment says *"screenshotted, not reasoned
  about"*, and that is the standard the rest of the audit should be held to.
- **The comment lives inside the `<div>` on purpose** (`:110-118`, spelled out on the twin at
  `:124-128`): one line higher it is the first child of a ternary branch, which is
  `infra-astro-comment-in-expression-ssr500` — both registries served **HTTP 500 with a 75-byte
  body** with every gate green. Do not "tidy" that comment upward.
- **`lastWriteRank`** (`:58-62`). A relative label has no time axis, so the duration form is parsed
  and everything else sorts to the end rather than being guessed a position. The comment names the
  exact bug it prevents (*"10m ago" before "2h ago"*) and names its own replacement (an ISO stamp
  from the backend). F7 is about the cell's *display*, not this.
- **`statusUnknown` as a NEW neutral entry rather than an alias** (`:30-45`). The argument — that
  borrowing an existing entry would either claim health or demand a reconnect, and both are lies —
  is the model for how this app should handle values it does not recognise. F3 exists because the
  detail page does not yet obey it; the list's version is the thing to converge onto.
- **`describeRegistryRemoval` + `wireRegistryRemove`** (`lib/registry/removal.ts`). One derivation,
  two object kinds, and its header states why: *"a six-line handler written twice drifts exactly as
  readily as a sentence written twice."* The copy names what survives, refuses to print a dependant
  count it has not counted, and explains why there is no Undo. **This is the shape F1/F3's fixes
  should take** — the module already exists and already has the right name.
- **Kind-aware copy that is genuinely kind-aware** (`:50-56`): `Per-Space schema` for a database and
  `Per-Space subfolder` for a file store, `Connection` vs `Writes to` as the field label. J08-F10's
  fix, and it is correct — do not collapse these back to one sentence.
- **The in-use guard on Remove is one button with `disabled` bound to the guard**, not two rendered
  branches (`:183-190`), and the dialog is therefore unreachable while dependants exist. Verified:
  `disabled: true` at 2 Spaces, `false` at 0.
- **The layout half of the edit contract is exactly right and was measured**: `.sch-slot` 32px in
  read, `.sch-slot-in` 32px in edit, `.reg-dl > div` 32px in both, `Test connection` going
  `visibility: hidden` rather than `display: none` so the card header does not reflow. Nothing
  moves. F1 is about the *state machine*, not this — a fix that disturbs these numbers has
  overshot.
- **The empty state's copy names the providers** (*Google Drive, Dropbox, Box, S3*) instead of
  apologising, and the header CTA yields to it so there is one primary. D17 working as intended.
- **The 390 floor gate.** *"This window is too narrow. Baseout needs at least 390px across."* It
