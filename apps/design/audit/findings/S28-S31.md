## 7 Cross-surface consistency

Against **Schema · Data · Reports**:

- **Pagination.** `decision-standardize-table-pagination` put one `TablePager` across Backups + Data
  + Schema. The picker hand-rolls a second one (finding 6) — and does it *inside the wizard too*,
  because the wizard embeds the same component.
- **Section tabs.** `/schema` and `/data` mount `watchSectionNav` (`SchemaView.astro:375`,
  `DataView.astro:342`); the wizard borrows their classes without it (finding 5).
- **Hit targets.** Every other checkbox in this table lives inside a full-width `<label>`. The two
  *workspace-level* controls do not (finding 3).
- **Empty states.** `pattern-empty-state`'s anatomy (icon · title · one mechanism sentence · one
  exit) is honoured by the wizard's own bases branch (`IntegrationsSetupWizard.astro:220`) and not by
  the standalone route hosting the same component (finding 10).
- **Cap wording.** Three sentences for one limit (finding 7) against `pattern-table-toolbar`'s
  one-construction rule and D19's one-vocabulary rule.
- **Failure vocabulary.** Two independent copy decks for the same eight OAuth codes (finding 2).
- **Alert colour.** `alert-soft alert-warning` still does double duty as the gate and the neutral
  heads-up (`:147` reused at `:781`) — **J01-F5**, instance.
- **Glyphs.** `lucide--hard-drive` (`:72`) vs `lucide--square-arrow-right-enter` (`:229`) for
  "destination", still 200px apart — **J01-F15**, instance.

## 8 Copy and tone

On-voice throughout: second person, no exclamation marks, verbs on buttons. The picker's band copy
is unusually good — it names the whole chain of an auto-enroll switch instead of its first link
(`:343`), and the limited-access sentence names the labels on screen ("they're **Workspace 1, 2,
3** — rename any below", `:308`). Defects:

- **Three sentences for one cap**, chosen by which control you touched (finding 7).
- **`/integrations/authorizing` promises a thing it cannot know.** "Confirming read-only access,
  then we'll set up your backup." asserts the outcome *before* the round-trip returns, on a page with
  no failure branch — so the last words a user sees before a failed connect are a promise it worked.
- **"Selected 0 of 10 (your plan's max)"** — a parenthetical selling the plan inside a count.
  Compare the picker's own cap note, which states the same fact once, properly, when it becomes true.
- `never (keep forever)` still lowercase among `1 year` / `2 years` (`:330`) — **J01**, instance.
- Review still names a count, not the bases (`:720`) — **J01-F20**, instance.

## What is good here — do not touch

- **The gate model, and the exit guard now beside it.** Next is never `disabled`, because "a disabled
  button cannot be attempted, and an attempt is exactly what earns the message" (`:775-779`); the
  guard that landed since J01 is delegated in the **capture phase on `document`**, so it covers the
  sidebar and not merely the two exits the page owns, and it **carries the intercepted destination
  onto the confirm link** so "yes, leave" goes where the user was going (`:836-892`). It also asks
  only when there is something to lose (`:862-865`). This is the best-argued code in the flow.
- **The workspace-resolution design.** A determinate bar pinned to the card's top edge (never a
  spinner — the percentage is known), held back 500ms so a five-base account never sees a blink
  (`:1535`), resuming from the count it was handed rather than restarting at 0, dropping to the
  **neutral** variant on failure because a lookup that gave up is not a page error (`:1546-1552`),
  and grouping the table with a FLIP transition rather than a skeleton over a ~0ms operation
  (`:1621-1635`). Every one of those choices is written down beside itself.
- **"Still matching" is not "No workspace."** Two tail buckets, never merged, because *"we haven't
  asked yet" and "we asked and there is none" are two different facts* (`:105-110`), each with its
  own em-dash tooltip explaining why its Auto-add cell is not a switch (`:637-642`). This is the
  single most disciplined piece of state modelling in the audit so far.
- **`AccessScopeNote`.** One component, two variants, one canonical sentence, grouped the way
  **Airtable's own consent screen** groups scopes — *"if our page says read-only and the next screen
  says 'will be able to edit', we lose there"* (`:14-17`). It replaced the same claim in six
  wordings across eight strings, and it explicitly refuses to cover Restore because Restore writes.
- **The name-swap contract.** A user's placeholder name is a stand-in and yields to Airtable's real
  name when it arrives; answering "Keep mine" *promotes* it to a deliberate choice and only then are
  both names shown (`:160-179`, `:1697-1726`). Reversible, announced once, expires when answered.
- **No "Auto-enrolled" badge**, with the reason recorded: arriving automatically is an event and a
  badge is a state, so it would never expire (`:594-600`).
- **The `:global()` discipline and the CSS comments around it.** `.bst-row` is rendered by a child
  component, so a scoped selector matches nothing and the table reflows into a paragraph of names —
  the bug happened, and the comment that prevents its return names the date and the symptom
  (`:824-829`). Same for the three comments warning that an Astro comment inside a ternary branch is
  a silent SSR 500.
- **The 390 pan decision, and its arithmetic.** 478px of fixed columns against 334px of width, with
  every floor a max-content measurement rather than a guess, and the rejected alternative named
  (`:1004-1025`). Finding 4 asks for one column to be re-placed inside that decision — it does not
  ask for the decision to be reopened.
- **Zero horizontal page overflow on all four routes at 390.** §9's protected number holds.
