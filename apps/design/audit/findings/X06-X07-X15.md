## 1 Job

**X06 — overlay model.** UNSTATED as a single rule. `specs/16-responsive.md` §8 ("Panels and
overlays") governs panel *width* and bans `vw`, and the catalog carries `modal`, `confirm-modal`,
`drawer` and `pattern-multi-panel-drawer` entries, but no spec anywhere answers *when a thing is a
modal versus a drawer versus a panel*. That absence is the finding this lens exists to record: seven
implementations exist because nothing ever said which one to reach for.

**X07 — clickability.** STATED, and stated well. `styles/components/row-actions.css:1-11` is the
contract: *"the ONE way an 'openable' table/list row behaves app-wide… Whole-row click / Enter /
Space opens the detail; the action icons stopPropagation."* The user's job is to open the thing
under the cursor, and to be able to tell before clicking whether it opens in place or navigates.

**X15 — keyboard, focus and escape.** UNSTATED. No spec, no catalog entry, and no `guides` line in
`storybook.ts` mentions focus trapping, focus restoration or tab order. Every keyboard behaviour in
this app is a local decision by whoever wrote the surface, which is exactly why they disagree.

## 2 First five seconds

Not a screen, so the equivalent question is: **what does the user learn in the first five seconds
that transfers to the next surface?**

- **X07 transfers well.** The `.row-go` chevron (`row-actions.css:22`) is persistent and identical
  on Backups, Restore, Sources, Destinations, Reports, Schema Browse, Relationships, Automations,
  Interfaces and the report bodies. A user learns "grey chevron on the right = this row opens" once.
  This is the single best-transferring affordance in the app and it should be protected.
- **X06 transfers badly.** Opening a table from Schema Browse gives a coplanar non-dimming panel
  that keeps the page live; opening "Failed attachments" from a backup run gives a 55%-black scrim
  that kills the page; opening the relationship detail gives a third thing that looks like the
  drawer but does not dim and does not stack. Three overlays, three mental models, no signal in
  advance about which one a control will produce.
- **X15 transfers not at all.** Whether Enter opens the row you focused depends on which file
  rendered it (§ Findings F5).

## 3 Navigation and orientation

- **Every list row in the app navigates by `window.location='…'`** — 12 sites (F4). None of these
  is a link. Consequence the user feels: middle-click, ⌘-click, "Open link in new tab" and
  right-click ▸ Copy link address are unavailable on every list in the product. On a utility admin
  tool whose core job is comparing runs and bases side by side, that is a real loss, not a purity
  argument.
- **One site does it right and proves the point:** `BackupRunDetailView.astro:446` puts a real
  `<a href={baseHref} onclick="event.stopPropagation()">` on the base-name cell *inside* the
  row-clickable `<tr>`. The row is a button, the name is a link, both reach the same href. It is
  the only one of the 12 where ⌘-click works.
- **Overlay state is not addressable.** The panel stack persists an arrangement to storage
  (`panelStack.ts:598` `type Saved`), so a refresh restores it — but a URL does not carry it, so the
  arrangement cannot be shared. `Drawer`'s state is a `<input type="checkbox">` (`Drawer.astro:33`,
  `:53`), which is neither in the URL nor persisted. Same job, two non-answers. This overlaps
  `audit/decisions/07-addressable-state.md`; recorded here as evidence, not re-filed.

## 7 Cross-surface consistency

**The reference for each lens, and the measurement that makes it the reference:**

**X06 → `Modal.astro` (`<dialog>` + `showModal()`) for anything modal; `PanelHost`/`panelStack` for
anything non-modal.** The measurement: `Modal.astro` is the only overlay in the app that gets focus
trapping, focus restoration and Escape *for free from the user agent* — zero lines of keyboard code
in the file, and it is correct in all three. Every other overlay hand-writes its Escape (5 separate
`document` listeners) and gets focus wrong. And `PanelHost` is the only overlay that survived a real
consolidation: `1c5ffa9` merged four `position:fixed; inset:0` roots into one host with a kind
registry (`PanelHost.astro:331`), which is why it alone has a cap, a rail, persistence and an
Escape that asks the panel's kind first (`:578`).

**The convergence list is therefore short and specific:** `SchemaDocs.astro:263` → `ConfirmModal`.
`SchemaRelationships` `.rl-detail` → a `PanelHost` kind. `Drawer` side=end/start → either gain real
modality or drop `aria-modal` and become a `PanelHost` kind. `Drawer` side=bottom → its own catalog
entry (`sheet`), because it is a different component wearing the same name.

**X07 → `.cl-entry` / `.dc-runrow` as a real `<button type="button">` (`global.css:2766-2772`).**
The measurement is in the file's own comment and it is the strongest argument in this audit:
*"a keyboard contract re-implemented per feed is the class of bug a real button never has."* The
changelog feeds converged there and consequently need **zero** keyboard code; the 11 files listed in
§5 that did not converge carry 11 copies of the same 3 lines, and 3 of those copies are missing
(F5). A `<tr>` cannot be a `<button>`, so for tables the ruling has to be the two-part one in F4.

**X15 → `pickerSearch.ts:997-1053`.** The measurement: it is the only keyboard implementation in the
repo that handles the *conflicts*, not just the happy keys — ←/→ yield to the caret until it is at
the end of the value (`:1006-1012`, so typing a correction still works), Escape unwinds one level
before it closes and `stopPropagation`s so the host's handler cannot eat the same keystroke
(`:1028-1031`), and Enter/Space are answered on both the input's ring and the focused list node
because "keyboard activation fires `click`, never `mousedown`" (`:1044-1053`). No other file in the
app reasons about a single one of those.

## 9 Foreign or surprising

**Three of this item's own starting facts are wrong. Correcting them is part of the deliverable.**

1. **"2 `<dialog>` but 14 `showModal()`" is not a defect — it is the system working.**
   `Modal.astro:35` is the single dialog factory; `ConfirmModal`, `RunBackupNowModal` and
   `CreateSpaceModal` all compose it, and the 14 call sites open dialogs those components rendered.
   All 14 were traced to a rendered id, **including the four conditional ones**, which are the ones
   that could have been dead and are not: `BackupRunDetailView.astro:280/281` (`pause-run-modal`,
   `cancel-run-modal`) are inside `{running}`/`{paused}` and their dialogs at `:499`/`:509` carry the
   same guards; `:312` and `BackupRunBaseView.astro:189` are inside `{failed}` and their
   `RunBackupNowModal` at `:521`/`:316` is `{failed &&}`. **No dead `showModal()` exists.** The one
   genuine finding in the neighbourhood is the *second* `<dialog>`, `SchemaDocs.astro:263`, which is
   hand-rolled (F6).
2. **"The picker drill takes Escape backwards but has no forward key" is stale.** ArrowRight drills
   forward (`pickerSearch.ts:1006-1013`) and Enter activates (`:1022-1026`). The picker is in fact
   the best keyboard surface in the app and this item nominates it as the X15 reference.
3. **"Row navigation found on seven sites" undercounts.** It is **twelve**, across nine files (F4).
   And "32 `cursor-pointer` uses" is 154 once `cursor: pointer` in CSS is included.

Genuinely surprising, beyond the findings:

- **`aria-modal="true"` on a region that is not modal** (`Drawer.astro:35`, `:56`) is the only place
  in the app where the markup asserts something about itself that the code contradicts. Two lines
  away, `QuickAskDock.astro:90` writes `aria-modal="false"` correctly. Same repo, same week.
- **`BackupRunDetailView.astro:731` contains a false comment**: "wired the same way Home and the
  Backups list wire theirs." Home does wire it (`SpaceHomeView.astro:508`); the Backups list does
  not wire it *in that file* — it inherits it from `runLog.ts:76`. The comment points a future
  implementer at a file where the code is not. Harmless today, S4.
- **`.rl-detail-scrim` is a scrim that does not dim** (`SchemaRelationships.astro:566`, "no
  dimming"). It is a full-viewport click-catcher with `pointer-events:none`, i.e. an element that
  exists but does nothing. Read as intent-drift, not a bug.

## 10 Density and rhythm

Nothing to file that is not already in the register. One measurement worth recording because it is
the *cause* of an X16 claim: the Drawer widths (F3) are a density problem only below a ~511px
viewport, because `min(94vw, 30rem)` and a literal `480px` are the same number at every desktop
width. The defect is real but its blast radius is narrow — that is why it should be a token
correction, not a redesign.

## What is good here — do not touch

These are load-bearing and an implementer working F1–F13 will be tempted to "tidy" them. Do not.

1. **`Modal.astro` is a native `<dialog>`, and `ConfirmModal`'s `returnValue` contract is excellent
   design.** `ConfirmModal.astro:17-25` makes the outcome observable through the *component's own*
   footer, and the comment explains exactly why that removed the pressure on every caller to supply
   a custom `confirm` slot and re-argue footer sizing. Escape, the backdrop and the ✕ all leave
   `returnValue` empty and read as "not confirmed" with no special case. Keep the unsized md footer
   pair; `:70`'s `ds-ok` already carries the reasoning.
2. **`.row-go`, the persistent quiet chevron.** `row-actions.css:22-24`. It is the one affordance
   in this app that a user learns once and finds identical on eleven surfaces. Every F4/F5 fix must
   preserve it exactly, including its two opacity steps.
3. **`.row-actions` are absolutely overlaid, deliberately, and the reason is written down.**
   `row-actions.css:27-32`: in-flow icons would widen the trailing column and force a horizontal
   scrollbar on the whole table. That is a measured decision, not a style choice.
4. **`.cl-entry` / `.dc-runrow` as real `<button type="button">`.** `global.css:2766-2772`. This is
   the correct answer already implemented and already argued. It is the X07 reference; do not
   "simplify" it back to a `div`.
5. **`pickerSearch.ts:997-1053`.** The caret-position guard on ←/→, the one-level Escape unwind with
   `stopPropagation`, and the mousedown-vs-click reconciliation at `:1044-1053` are three separate
   traps solved correctly in one file. It is the X15 reference and it should be lifted into the
   catalog verbatim, not rewritten.
6. **`PanelHost`'s Escape delegation.** `PanelHost.astro:568-579` — one handler that asks the
   focused panel's *kind* rather than peeking at another stack's DOM. Its comment names both hacks
   it replaced. F1 adds DOM focus to this file; it must not disturb this handler's shape.
7. **`PanelHost.astro:582-591` — tab changes no longer close the stack.** This was a real user
   complaint (Dan + Oleh, 2026-08-05), the fix is correct, and the comment records that the measured
   behaviour contradicted what everyone believed. Leave it.
8. **`entityPanelController.ts:667-711`.** The only place in the app that reads `document.activeElement`
   to preserve a user's position across a re-render (edit zone, sub-add input, picker). F1's focus
   work must compose with this, not replace it.
9. **`QuickAskDock.astro:90` — `aria-modal="false"`.** The one honest modality declaration in the
   repo. It is the model for F2's resolution.
