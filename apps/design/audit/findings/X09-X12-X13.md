## 1 Job

- **X09 — icons.** A glyph tells the user *what kind of thing a row is* before they read it, and
  tells them the same thing on every surface. `decision-entity-glyphs`: "a glyph where the row KIND
  varies", `entityIcon.ts` is the ONE map.
- **X12 — navigation and IA.** The user must always know where they are, how to leave, and be able
  to **send the view to a colleague**. Authority: `audit/decisions/07-addressable-state.md` (D07),
  already adjudicated — "every position is in the URL, every instance page is titled by its
  identity". This lens does not re-open D07; it measures how much of the app has arrived there.
- **X13 — copy and tone.** `specs/00-design-principles.md:139-151` ("Direct, second-person, short
  sentences"; status copy descriptive not promotional; no exclamation points / "Awesome!") and
  `specs/01-naming-and-hierarchy.md:128` (person vs system voice). Stated, not UNSTATED.

## 2 First five seconds

Not a screen lens, so the five-second test is applied to the *recognition* each lens is responsible
for. Two of the three fail it in a way a user meets on the first session:

- The **base** concept is blue and the **table** concept is green wherever `entityIcon.ts` painted
  them (`styles/global.css:2538-2563`) — and grey wherever a surface hand-rolled the same glyph
  (`lib/refineFacetIcons.ts:47`). On the Attachments tab both appear **on one screen at once**
  (refine panel vs group headers), so the colour cannot be read as meaning anything.
- The **address bar** answers "where am I" on `/data?tab=comments&cmq=signature` and answers nothing
  on `/schema` after nine tab clicks and four facet choices. Two sections, same shell, opposite
  contracts.

## 3 Navigation and orientation

**The app has THREE breadcrumb systems and only one of them is alive.**

1. `components/ui/Breadcrumbs.astro` — **zero importers anywhere in `apps/web`** (`git grep -a
   Breadcrumbs -- 'apps/**'` returns only `apps/design/src/lib/storybook.ts:1581-1585`). It is the
   catalog's **named reference** for the Breadcrumbs entry, and no screen has ever rendered it.
   It escaped the repo's dead-view sweep because CLAUDE.md's check only walks `views/*.astro`.
2. `lib/config.ts:92 getBreadcrumbs()` — computed by **25 harness pages**, passed into
   `layouts/SidebarLayout.astro:27,54`, JSON-serialised into `#page-header-state`
   (`SidebarLayout.astro:136`), parsed into `stores/pageHeader.ts:15` by
   `components/layout/Header.astro:64-77` — and **never painted**. `Header.astro:83-92` paints only
   `title`. `global.css:480` says it out loud: "the title the topbar script has always been parsing
   into `$pageHeader` and never rendering." A whole data pipeline exists for a UI that does not.
3. The live one: `<div class="breadcrumbs text-sm py-0">` hand-rolled in **six places** —
   `BackupRunBaseView.astro:132` · `BackupRunDetailView.astro:219` **and** `:234` (twice in one
   file) · `ReportDefinitionView.astro:115` · `ReportDetailView.astro:72` · `RestoreView.astro:209`.
   Four of those carry a comment calling it "daisyUI primitive (catalog)" — the catalog entry they
   name points at the dead component.

**Drawer trails are a fourth system, and it forks.** `components/schema/locationCrumbs.ts:7` says
"Every drawer uses this — never hand-roll a breadcrumb". `components/data/recordReadBody.ts:338-343`
hand-rolls one anyway. The consequence is behavioural, not cosmetic: `locationCrumbs.ts:30-32`
renders an ancestor with `openAttrs` as a **`<button class="sb-crumb-link">`**, while
`recordReadBody.ts:339` has no clickable branch at all — every segment is a plain `<span>`. So the
Base ▸ Table trail is **clickable in the Attachments panel** (`mediaReadBody.ts:216` → locationCrumbs)
and **dead text in the Record panel** (`DataChangelog.astro:746`, `RecordPanel.astro:119`), on two
panels of the same Data section, styled identically.

**Section tabs.** `components/ui/sectionTabs.ts` is the ONE controller and it is good: it restores
from `?tab=`, writes back with `replaceState` (:54, with the Back-must-leave reasoning at :16-18),
degrades a stale link instead of blanking (:72-78), and dispatches `app:tabchange` so drawer stacks
close. **Three hosts use it**: `DataView.astro:355`, `SchemaView.astro:387`,
`ReportDefinitionView.astro:743`. `IntegrationsSetupWizard.astro:793-821` runs its own step
controller writing `?step=` — a documented, argued fork, not drift.

**Correction to the brief:** "Schema's nine tabs are not addressable by any query param" is
**no longer true**. `SchemaView.astro:382-394` wires `wireSectionTabs`, and all nine `data-tab`
keys (browse · visualize · relationships · changelog · health · docs · chat · automations ·
interfaces) resolve. That scout finding is superseded; what remains is the gate gap (§6).

**Section nav overflow** (`lib/sectionNavFit.ts:1-16`) moves whole labelled clusters into an
overflow menu rather than wrapping, because a wrapped cluster label captions tabs that are not its
own. This is one of the better-argued pieces of navigation code in the repo.

## 7 Cross-surface consistency

**The URL contract, as the app actually defines it.** Two modules state it and they are consistent
with each other and with D07:

> A section's **position** is `?tab=`, owned by `sectionTabs.ts`. Everything **below** the tab —
> search, facets, group-by, date range, and the selected item — is a declared key owned by
> `viewState.ts`. Both write with `history.replaceState`, never `pushState`, so **Back leaves the
> section rather than undoing a keystroke** (`sectionTabs.ts:16-18`, `viewState.ts:17-20`). A field
> at its default is **deleted** from the URL, never written empty — "the address of an untouched
> page is the bare page" (`viewState.ts:19-20`). A param naming something this page does not have is
> **skipped**, so a stale link degrades to a working page rather than an empty one
> (`sectionTabs.ts:72-78`, `viewState.ts:103-105`).

That is a genuinely good contract. Where it breaks:

| break | evidence |
|---|---|
| 13 of 15 filterable surfaces keep state out of the URL | `FacetFilter` is rendered by `DataBrowse` · `DataChangelog` · `DataComments`✓ · `DataMedia`✓ · `SchemaBrowse` · `SchemaChangelog` · `SchemaAutomations` · `SchemaInterfaces` · `SchemaRelationships` · `SchemaCanvas` · `ReportBodyKpi` · `BackupsListView` · `ReportsView` · `RestoreHistoryView` · `inbox-client`. Only the two ✓ import `wireViewState` |
| all nine Schema tabs share one un-addressable sub-state | a colleague can be sent `/schema?tab=health` but not "Health, filtered to the two bases with issues" |
| the search box of 11 surfaces is not in the URL | `data-sch-search` hosts: `DataBrowse` · `DataChangelog` · `DataComments`✓ · `DataMedia`✓ · `EntitySearch` · `SchemaAutomations` · `SchemaChangelog` · `SchemaInterfaces` · `SchemaRelationships` + the two view shells |
| `/reports/[id]` reads no `?fixture=` | so the report definition page has no empty / no-backups render at all, in a repo whose whole preview model is `?fixture=` |
| page-level breadcrumbs are computed and discarded | §3 item 2 |

## 8 Copy and tone

**Dates — three relative-time implementations, and two of them disagree arithmetically.**

| impl | grammar | rounding | tail |
|---|---|---|---|
| `lib/time.ts:142 fmtRelative` — **the reference** | `just now` · `5m ago` · `3h ago` · `12d ago` | `Math.round` | unbounded days |
| `views/ReportsView.astro:33 since()` | identical strings | `Math.round` | unbounded days — a character-for-character duplicate of the reference, in a reference surface |
| `components/layout/inbox.ts:222 ago()` | `now` · `5m` · `3h` · `3d` (**no "ago"**) | `Math.floor` | switches to `fmtDayShort` after 7 days |

The disagreement is provable without a browser: an event **90 minutes** old prints **`2h ago`**
via `fmtRelative` (`round(1.5)`) and **`1h`** via `inbox.ts` (`floor(1.5)`). Home and the Inbox are
read together, and the Inbox is the surface that tells you a backup broke. `inbox.ts:225-231` also
drops the word "ago" entirely, so `3d` in the Inbox and `3d ago` on Home are the same fact in two
grammars. `inbox.ts:232-235` carries a *correct* D09 note about locale pinning — the module knows
this class of bug exists and still forked the arithmetic.

Separately, **15 files call `toLocale*` directly** rather than `lib/time.ts`
(`DataChangelog` ×5 · `DataMedia` ×5 · `recordReadBody` ×5 · `ExportControl` ×4 · `tablePager` ×3 ·
`runReadBody` ×2 · `SchemaBrowse` ×2 · `SchemaDocs` ×2 · `DataComments` ×2 · `DataBrowse` ·
`MediaPanel` · `RecordPanel` · `StaticImport` · `schemaReadBody` · `pickerSearch`). `time.ts` pins
`LOCALE`; a bare `toLocaleString()` does not. **Which of these 15 omit the locale argument is
`NEEDS-MEASUREMENT`** — read each call site, or diff a render under `LANG=en-GB`; it is the exact
bug `inbox.ts:232` documents ("`14 Jul` in review and `Jul 14` for the US customer").

**Counts — three grammars, one of which switches inside a single control.**
`SchemaBrowse.astro:906` prints `Showing ${visible} of ${total}` when a filter is on and
`${total} entities` when it is off — the label *changes shape* as you filter, so the number moves
and the noun appears and disappears. `ReportsView.astro:110` prints `Showing N of M` always, with
both numbers in `mono-data` spans so the digits do not jitter. `runReadBody.ts:126` prints a third
form, `Showing the N sampled of M — open the backup for the full list`, which is longer but is the
only one that says *why* the two numbers differ. **Reports is the reference** and the measurement is
`mono-data` plus grammatical invariance: it is the only count that keeps one sentence shape and one
digit width across every state.

**Failure copy — the product wrote it well and ships the other one.** Nineteen documented failure
messages sit in `views/IntegrationsView.astro`, a file whose own header (`:2-18`) states no route
renders it and that it is a **copy deck, not a screen**: ten connect codes at `:50-61`, nine
rescan codes at `:489+`. They are in-voice per `specs/00:141`:

> `missing_handoff`: "Your session expired before Airtable returned. Please try again."
> `state_mismatch`: "Security check failed. Please start the connection over."
> `api_call_failed`: "We connected to Airtable but could not list your bases."

The *live* set for the same eight codes, `StoragePicker.astro:476-493`, is written in
implementation language:

> `missing_handoff`: "Your browser dropped the OAuth handoff cookie during the round-trip. Try
> again — if it keeps happening, allow cookies for this site."
> `state_mismatch`: "The OAuth state parameter didn't match what we sent — this can happen if you
> complete the flow in a different browser tab."

and prints `error_code: <code>` beneath it (`:501`). It also uses typographic apostrophes
(`didn't`, `isn't`) where `IntegrationsView` uses ASCII — the same paragraph, two character sets.
The live one is not *worse* everywhere: "allow cookies for this site" is the only actionable
remedy either set offers, and the printed code is right for a technical ops user. The defect is
that the two exist at all, and that the Airtable side — the connection this product is *for* —
renders **none of its nineteen**.

**Tone hygiene is otherwise clean.** No exclamation marks in user-facing copy (the seven `!` hits
are all inside comments about *not* writing a "resolved!" notification), no "Awesome"/"Oops",
no mascots. Button labels are verbs where sampled (`Create report` / `Save changes` /
`Go to Backups`). This part of `specs/00:139-151` is being honoured.

## 10 Density and rhythm

Icon sizing is disciplined and worth recording as a pass: **`size-4` (455) · `size-3.5` (305) ·
`size-3` (45) · `size-5` (13) · `size-6` (12) · `size-7` (4)** across `apps/web/src`. Nothing below
`size-3` (12px), so the CLAUDE.md sizing floor holds everywhere. The two dominant sizes map to a
real distinction — 16px for controls and table cells, 14px for chips, crumbs and feed rows
(`global.css:2632,2655` pin `.sb-chip-ic`/`.sb-crumb-ic` to 14px). **73 `class="iconify lucide--*"`
spans carry no size utility at all** and inherit 1em from context; whether any of those lands below
12px is **`NEEDS-MEASUREMENT`** — the mechanism is `global.css:1503` (the mask is 1em, so the icon
is font-size), so it needs a computed `font-size` per site, not a reading.

One colour-cascade risk, from source: `global.css:2538` colours **every** `.iconify.lucide--table-2`
green at specificity (0,2,0). `RestoreView.astro:345` and `:643` ask for
`lucide--table-2 text-base-content/45` — a (0,1,0) utility in a Tailwind layer, which loses. So the
Restore tables' muted-icon intent is almost certainly not painted. **`NEEDS-MEASUREMENT`** —
one `getComputedStyle(el).color` on `/restore` settles it. The same global rule contradicts its own
justifying comment ("`table-2` is used ONLY as the table-entity icon, so it can be coloured
globally"): it is also the **Records tab** icon (`DataView.astro:176`), the wizard's **Bases step**
icon (`IntegrationsSetupWizard.astro:71`) and the **"Airtable copy" tab** icon
(`SchemaAutomations.astro:303`) — three navigation controls wearing the entity-concept colour.
