Executive summary

The single most useful finding: the AI-model "playground" is a nearly exact analog of what Baseout needs. Braintrust, Chatbase and Cloudflare's AI Gateway all render N independent, equally-weighted panels in a horizontal strip, each with its own header, a per-panel close ×, an "Add an instance" / "+" to append a new one, a per-panel "Sync" toggle so scrolling/input mirrors across panels, and workspace-level "Reset" / "Clear all" controls (Chatbase compare, Cloudflare AI Playground, Braintrust). That is the closest shipped precedent to a schema-entity comparison workspace, and most of the mechanics below are already validated there.

Across the five dimensions the recommendations converge on a coherent model for a dense admin tool:

  • Navigation: a persistent panel-header strip (each panel is self-labeling) plus keyboard cycling; a "which is active" ring; a jump/overflow menu once panels exceed the viewport.
  • Adding: keep the literal "+" but pair it with a "Compare with…" picker (HubSpot's explicit compare-picker, capped at N) and multi-select → open side-by-side from the schema list.
  • Managing: per-panel ×, plus close-others / close-all, drag-reorder, pin, and save-a-set (a named comparison you can reopen) — all with precedent.
  • Layout: equal widths by default, drag-dividers for weighting, collapse-to-rail for a parked panel, and one-panel focus/full-width — all standard in react-resizable-panels-class libraries and VS Code editor groups.
  • Overflow (the hard one): cap the tiled panels at what fits (≈2–4), horizontally scroll a panel strip beyond that, collapse older panels to a rail, and expose everything through an overflow menu. This is the union of the AI-playground strip and VS Code's tab-overflow model, and it degrades gracefully — see the recommendation.

1 · Navigating between panels

Once there is more than one panel, the user needs to answer three things constantly: which panel am I acting on, how do I move focus, and how do I reach one that's off-screen.

Self-labeling panel headers + active ring

The playground pattern gives every panel a header with the entity name and its own controls; the focused one is distinguished visually. Because each schema panel already shows a base/table/field name, the strip of headers is itself the tab bar — no separate tab row needed.

proven Braintrust, Cloudflare · fit zero new chrome

Keyboard cycling & close

Detail panels routinely bind focus/close to keys — Notion's side peek documents Ctrl-Shift-\ to close, and IDEs cycle editor groups with keyboard commands. For a power-user ops tool, [/] or ⌘1…9 to focus the nth panel and ⌘W to close the focused one are cheap and expected.

proven Notion side peek, VS Code

Breadcrumb / hierarchy context per panel

Because Baseout entities live in a strict hierarchy (Base → Table → Field), each panel header can carry a compact breadcrumb so a lone Field panel still says which Table and Base it belongs to. This is the two-panel-selector discipline — list context on one side, detail on the other — applied per panel. proven Side-by-side pattern, two-panel selector

Minimap / overview: a small "N panels open" indicator that expands to a list of all open panels (jump-to on click) becomes worthwhile only past ~4 panels. Precedent is Stage Manager's thumbnail strip and command-palette "recents". Treat as a speculative add-on gated on the overflow case, not a v1 requirement. (Stage Manager)

The literal ask is a "+". The research says a "+" alone is the weakest affordance because it doesn't tell the user what they'll add. Pair it with a picker and with multi-select entry points.

3 · Managing panels (open / close / reorder / persist)

Per-panel close + close-others / close-all

Each panel header carries an ×; the workspace carries "Reset" / "Clear all". The browser-tab right-click set — Close, Close Others, Close to the Right, Close All — is the mature vocabulary and users already know it.

proven Braintrust "Clear all / Reset", VS Code close-group

Drag-reorder + duplicate

VS Code lets you drag editor tabs/groups to reorder and reposition. Duplicating a panel (same entity, second copy) is useful to compare two states of one entity — e.g. current vs a changelog snapshot.

proven reorder — VS Code custom layout · speculative duplicate-for-diff in a schema tool

Save-a-set / named comparison

A saved set of panels you can reopen ("Airtable → Orders vs Line Items"). Direct precedent: Edge/Arc Workspaces persist by default where tab groups don't; terminal tools (Warp, tmux-resurrect) save and restore named window/pane layouts by name.

proven Edge Workspaces, Warp sessions

Persist across reload

Layout libraries (react-resizable-panels) ship localStorage persistence; VS Code "remembers the layout across sessions". For a read-only inspector, persisting which panels + their widths to localStorage is low-risk and removes the "set it up again every time" tax.

proven react-resizable-panels, VS Code

Detach (pop a panel into its own window) is common in IDEs but is heavy for a web admin tool and low-value for read-only inspection — speculative, recommend deferring.

4 · Resizing & layout

This dimension is the most solved. The react-resizable-panels / shadcn Resizable / Ant Splitter family gives, out of the box, exactly the toolkit needed:

  • Drag-dividers between panels with col-resize cursor affordance; keyboard-resizable and ARIA-announced.
  • Equal vs weighted widths — default to equal; let a divider drag give one panel more room (e.g. the field with a long formula).
  • Collapse-to-rail — collapsedSize parks a panel as a thin labeled rail instead of hiding it (double-click divider to collapse/expand).
  • Full-screen one panel — a "focus / maximize" that hides the rest, mirroring Stage Manager's centered window and VS Code's maximize-group.
  • Min/max constraints + snapping + persisted sizes so panels never collapse to unreadable slivers.

proven react-resizable-panels, shadcn / ReUI Resizable, Ant Design Splitter

Responsive / mobile: side-by-side breaks down on narrow viewports. The tabs research is blunt — past ~4–5 targets a row is cramped and horizontal scroll is the honest fallback. On mobile, collapse the comparison to a single-panel view with a tab strip / swipe between panels (Microsoft dual-view guidance: on one screen, fall back to a master-detail single pane). proven tabs UX, MS dual-view. This matches the existing Schema decision that mobile falls back to primitive tab scroll.

Sync / linked panels (comparison super-power)

Diff tools and the AI playgrounds both offer synchronized scrolling + a per-panel Sync toggle so the panes stay aligned while you compare, plus a Diff highlight mode. For schema, a "sync sections" toggle (scroll all panels to the same section — Fields, Relationships, Health) and a "diff" mode that highlights where two tables/fields differ would be genuinely differentiating. proven (adjacent domain) Braintrust Sync/Diff toggles, Araxis 2/3-way, Beyond Compare / Meld synced scroll (diff-tools guide).

Overflow strategy — concrete recommendation

Adopt a "scrolling strip with a soft tile-cap, a collapse rail, and an overflow menu." Concretely:

  1. Give every panel a readable min-width (e.g. ~320px). The panel strip lays them out horizontally.
  2. Tile as many as fit the work area (typically 2–4 at Baseout's density), with the focused panel carrying an active ring. Show a peek of the next panel as the scroll affordance.
  3. Beyond what fits, the strip scrolls horizontally — no shrinking panels into illegibility. Panels the user has "parked" can collapse to a thin labeled rail to hold context cheaply.
  4. An overflow "N more ▾" control lists every open panel for jump-to (and reorder/close). This is also the mobile fallback: collapse to a single panel + this list as a tab strip.
  5. Soft-cap the count (offer to close the oldest at, say, the 6th–8th) rather than a hard refusal — matches HubSpot's "up to N" and the tabs-UX "set a limit" guidance without frustrating the power user.

This is the union of the closest shipped analog (AI-model playgrounds add instances into a scrolling strip) and the most mature overflow vocabulary (VS Code / adaptive-tabs scroll + "More" menu). It degrades gracefully from 2 → many → mobile, needs no exotic component, and stays in the Linear/Vercel/Plaid register. Reserve Stage-Manager stacks and window-detach as later, speculative flourishes only if users actually hit double-digit panels.
