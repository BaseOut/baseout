1 · What Baseout Is

"Baseout is the backup, restore, and data intelligence layer for Airtable — giving platform admins real-time protection, schema visibility, and direct SQL access to their own data."

B2B SaaS utility that automatically backs up Airtable (schema, records, attachments, plus user-submitted automations/interfaces) to customer-controlled or Baseout-managed storage, provides restore, and layers on data intelligence: schema visualization & changelogs, base health scoring, documentation, analytics, and — on higher tiers — a live SQL copy of the customer's data with API access. V1 is Airtable-only; the architecture is built for multi-platform expansion (Notion, HubSpot, Salesforce) with per-platform subscriptions under one billing relationship.

2 · Business Context — a Relaunch, Not a Cold Start

Baseout is the full rebrand and next-gen replacement of On2Air Backups: ~200 paying customers (anchored at $9.99–$79.99/mo) migrate onto Baseout tiers. On2Air was, by the team's own assessment, historically underpriced relative to value. A detailed migration plan already exists (year-1 bridge pricing, two non-public plans, migration credit grants) that new pricing must stay compatible with. Competitive set is thin: Airtable's native snapshots (free, but not an external/governed copy), Whalesync, Coefficient, DIY scripts. Claimed differentiators: most storage destinations in market (only OneDrive support) and unique BYOS/BYODB — on static bring-your-own-storage plans, record data never touches Baseout servers.

7 · Cost Structure

Fully serverless/usage-based stack — near-zero COGS at rest, scales with activity: Cloudflare Workers + Durable Objects (web, engine, per-connection rate limiting, per-Space scheduling), Trigger.dev v3 (per-second compute for backup tasks), DigitalOcean PostgreSQL master DB, Cloudflare D1/R2/KV/Email, Workers AI, Stripe (~2.9% + 30¢), PostHog, dub.co. The Airtable API is free — its rate limits, not dollars, are the constraint.

Structural cost notes

  • Storage persists; credits reset — retention-heavy tiers accrue COGS monthly; Smart Cleanup is the containment feature (not yet built).
  • Dynamic incremental sync is cheaper for Baseout AND customer — the credit model nudges users toward the mode that also unlocks upsell.
  • Step costs: support (chat at Business, CSM/SLA at Enterprise) and SOC 2 certification (prereq for selling Business+).
⚠ Biggest structural margin risk — Business tier ($399/mo) includes a dedicated PostgreSQL instance per Space (~$19–60+/mo COGS each) with unlimited Spaces. Ten Spaces could cost more to serve than the subscription earns. Options: cap included dedicated-DB Spaces, provision per-Organization instead of per-Space, or price extra dedicated-DB Spaces as an add-on.

8 · Reality Check — Spec vs. Shipped Code (July 2026)

✓ Built & working

  • Backup pipeline end-to-end: OAuth, scheduled (per-Space DO alarms) + manual runs, per-base Trigger.dev tasks, CSV + attachment export w/ dedup, run history/cancel/delete, per-connection rate limiting
  • Destinations: managed R2, Google Drive, Dropbox, Box, OneDrive (S3/Frame.io stubbed)
  • Stripe skeleton: customer + subscription at signup, 7-day/1-run trial enforcement, subscription-item-per-platform, tier resolution
  • Tier gating in code: frequency, bases/Space, schema-docs level
  • Auth (magic link), dashboard, integrations/destinations UI, schema browsing, staff admin console

✗ Designed but NOT implemented

  • Entire credit system — no buckets, ledger, rates, or consumption logic; code has a simpler overage table that nothing populates
  • Overage metering/billing — revenue leakage until built
  • Restore — placeholder page only (a headline feature of every tier)
  • Retention/cleanup — storage grows unbounded (COGS risk)
  • Dynamic DB provisioning, webhooks/instant, Inbound API, SQL REST, Direct SQL — placeholder Workers
  • Seat/storage quota enforcement; analytics; health score UI

Sequencing decision: launch pricing can (a) start with what's enforceable today — flat tiers + frequency + bases caps + trial — layering credits/overage in later, or (b) hold launch for the credit meter. The gap between designed and enforceable models is currently large. Code tier limits also drift from spec (e.g., bases/Space 5/10/15/25/50 vs spec 1/3/3/∞) — treat code values as provisional.
